Part 2: Virtualization with Docker

This is a follow-up tutorial to my previous blog post covering the basics of setting up a Flask web server, so this tutorial will assume you have followed that one or already have your own Flask app you wanna virtualize (though if you already had one you probably don't need to read this).

This will be a relatively simple process as all we have to do is create a Dockerfile and a Docker Compose file to build an image and set up an easy way to create and shut down the container when needed.

So let's start by installing Docker. You can install it from here. for eithe Linux, Windows, or Mac. Once you have that you can navigate back to your project folder and create a file simply named Dockerfile, where you can put in the folliwng lines:

# This first line is the image that ours will be based on, since we're using Flask our image should be based on the official python image, I'm personally using version 3.12 but you can use any. However it's advised you don't use the latest version as it has the chance to make our image not function properly.

FROM python:3.12

# This next line tells our image which directory our app is stored, so let's go ahead and call it /app. However, it's really up to you what you wanna call it ^-^.

# P.S. It looks cleaner if we have an extra blank line in between each of our lines of code.

WORKDIR /app

# Now we want to copy our requirements.txt file over to our container's /app folder (represented by a period, which stands for "current directory") from our project folder.

COPY requirements.txt .

# Now we have to tell our container to use pip, which is python's module installer so that the import lines in our app.py file will work.

RUN pip install -r requirements.txt

# It's time to copy our whole project folder over to the /app folder. Just like in the previous COPY line we will represent our current directory (our project folder) and the container's current directory (the /app folder) with a period, so it will look a bit silly with just two periods after the COPY.

COPY . .

# The following line is optional for now as nothing in our container needs access to our app's port right now since our app is the only image we're running, but it will be necessary when we add our SQL database to connect to our app. But what this line does is it tells our app container to expose port 5000 so that any other containers in our project's Docker network can connect to our app.

EXPOSE 5000

# Lastly, we have to tell our container to run our app, without this, the container will start, but our app won't run so we won't be able to see our site.

CMD ["python", "app.py"]

Now we're able to create an application container that's isolated from the rest of our computer. We can test that our Dockerfile works by running the command docker build -t website:Dockerfile and then docker run website in our terminal. Alternatively, we can write a Docker Compose file named docker-compose.yml to run our container. This way will be super useful when we start adding other containers that we'll want to run at simultaneously with our website container. So let's do that. In our docker-compose.yml file, type in the following:

# This line lists our containers, we need it even though we just have one.

services:

# Tab in and write the line below. This line will define our container.

web:

# Tab in again and write each of the following lines:

build: . # This line tells our container and image from a Dockerfile in the specified location,

# which is the current directory (once again represented by a period).

container_name: flask_app # This line gives our container a name so that we can identify it easily

# if we need to check it's logs or something.

ports: # It's time to define our ports, so make sure you tab in and add the following line.

- "5000:5000" # This line specifies port 5000 as both the host port (the one before the colon)

# and the container port (the one after the colon) to serve the app on.

Supa fwickin' awesum sauce !! These two files let us build and run our app in an isolated environment via Docker. We can test that everything is functional by running the command docker compose up --build -d from the terminal. It'll take a few seconds for the image to be built and for the container to be created, but once it's up and running we should be able to navigate back to http://localhost:5000 and see our website. If we can't we can run it back without the -d and once the container is up an running we'll be ablte to see the logs to find out what's going on, and simply type d to exit out of the logs if we wanna turn the container off.

Well, that's it for this section of the website tutorial. If you made this this far, thank you for reading!! The next part of this tutorial will be soon!
